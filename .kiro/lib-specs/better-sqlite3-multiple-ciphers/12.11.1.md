## API Surface
`require('better-sqlite3-multiple-ciphers')` (or `import Database from ...`) exports a single `Database` constructor: `new Database(filename?, options?)`, also callable without `new`. Options: `readonly`, `fileMustExist`, `timeout`, `verbose`, `nativeBinding`.

**Database instance**: properties `memory`, `readonly`, `name`, `open`, `inTransaction`; methods `prepare(sql)`, `transaction(fn)`, `exec(sql)`, `pragma(sql, options?)`, `key(buffer)`, `rekey(buffer)`, `function(name, [options], cb)`, `aggregate(name, options)`, `loadExtension(path)`, `close()`, `defaultSafeIntegers(bool?)`, `backup(destFile, options?)` (async, returns Promise), `table(name, virtualTableOptions)`, `unsafeMode(bool?)`, `serialize(options?)`.

**Statement** (from `prepare`): `run(...params)`, `get(...params)`, `all(...params)`, `iterate(...params)`, `bind(...params)`, `pluck(bool?)`, `expand(bool?)`, `raw(bool?)`, `safeIntegers(bool?)`, `columns()`; properties `database`, `source`, `reader`, `readonly`, `busy`.

**Transaction** (from `db.transaction(fn)`): callable wrapper plus `.deferred()`, `.immediate()`, `.exclusive()`, `.default()` variants.

`Database.SqliteError` (also exported as `SqliteError`) extends `Error` with `code`. Encryption is exposed entirely through `PRAGMA` statements (`key`, `rekey`, `cipher`, `legacy`) or the `key()`/`rekey()` convenience methods, not a separate encryption API.

## Usage Patterns
- Synchronous, blocking API by design (no async/await/callbacks except `backup()`). One connection per process/thread is typical; use worker threads for large/slow queries rather than trying to make calls async.
- Enable WAL mode after opening: `db.pragma('journal_mode = WAL')`.
- Wrap multi-statement writes in `db.transaction(fn)` and call the returned wrapper rather than issuing manual `BEGIN`/`COMMIT` via `exec`.
- Encrypt/decrypt via pragma strings: `db.pragma("rekey='secret-key'")` to set/change a key on an existing (plaintext) db, `db.pragma("key='secret-key'")` to open an encrypted db. For legacy SQLCipher-created files (e.g. from DB Browser for SQLite): set `cipher='sqlcipher'` and `legacy=4` pragmas before the `key` pragma.
- Use `.pluck(true)` for single-column results, `.raw(true)` for array rows instead of objects, `.safeIntegers(true)`/`db.defaultSafeIntegers(true)` when 64-bit values must round-trip exactly as BigInt.
- Register custom SQL functions/aggregates with `db.function()`/`db.aggregate()`; mark them `deterministic`/`directOnly` when appropriate for planner optimization and safety.
- Use `iterate()` instead of `all()` for large result sets to avoid buffering everything in memory.
- For GUI inspection, prefer SQLiteStudio (uses SQLite3MultipleCiphers) over DB Browser for SQLite, since databases created by this library aren't necessarily openable by DB Browser unless using the legacy SQLCipher path.

## Anti-Patterns
- Don't treat this as an async library or wrap calls in Promises/callbacks "for consistency" with other DB drivers — the synchronous API is the whole point (better concurrency and no mutex thrashing vs. `node-sqlite3`).
- Don't run many individual `INSERT`/`UPDATE` statements outside a transaction in a loop; wrap in `db.transaction()` — un-batched writes are dramatically slower (up to ~15x in the project's own benchmarks).
- Don't use it for high-concurrency-write workloads (e.g. social-media-style apps), very large (near-terabyte) databases, or workloads needing many concurrent multi-megabyte reads — reach for PostgreSQL/a full RDBMS instead.
- Don't assume a database file encrypted/written by this library is editable in DB Browser for SQLite unless created via the explicit legacy SQLCipher pragma path (`cipher='sqlcipher'`, `legacy=4`).
- Don't call blocking, slow queries directly on the main thread of a latency-sensitive server; offload to worker threads instead.
- Don't bypass parameterized `prepare()`/`bind()` calls by string-concatenating user input into SQL, including into `pragma()`/`exec()` calls.
- Avoid `unsafeMode()` unless you specifically need its advanced/low-level behavior; it disables safety checks and is documented as advanced/risky.
