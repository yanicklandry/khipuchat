## API Surface
The library exports `BeeperDesktop` as the default client class (also named export), instantiated with `new BeeperDesktop({ accessToken, ... })`. Core surface:

- **Client construction**: `BeeperDesktop({ accessToken, timeout, maxRetries, logLevel, logger, fetch, fetchOptions })`; `accessToken` defaults from `process.env['BEEPER_ACCESS_TOKEN']`.
- **Resources** (namespaced methods on the client), inferred from examples: `client.accounts.list()`, `client.chats.search()`, `client.chats.create()`, `client.messages.search()`, `client.assets.upload()`.
- **Type exports**: `Uploadable`, `toFile`, `APIPromise`, `BaseBeeperDesktop`, `ClientOptions`, `PagePromise`.
- **Error classes**: `BeeperDesktopError`, `APIError` (base), and status-specific subclasses `BadRequestError` (400), `AuthenticationError` (401), `PermissionDeniedError` (403), `NotFoundError` (404), `ConflictError` (409), `UnprocessableEntityError` (422), `RateLimitError` (429), `InternalServerError` (5xx), `APIConnectionError`/`APIConnectionTimeoutError`/`APIUserAbortError` (network-level, no status).

- **Escape hatches**: `client.get/post/...` for undocumented endpoints; `.asResponse()` and `.withResponse()` on `APIPromise` for raw `fetch` `Response` access.
- Dual CJS/ESM build via `exports` map; subpath imports (`/client`, `/error`, `/pagination`, `/resource`, `/resources/*`, `/uploads`, `/version`) are all part of the public surface.

## Usage Patterns
- Instantiate one client per process/app, reusing it across calls rather than constructing per-request.
- List/search endpoints (e.g. `chats.search`, `messages.search`) return paginated results: use `for await...of` directly on the call for auto-pagination, or manually via `page.items`, `page.hasNextPage()`, `page.getNextPage()`.
- File-upload params (e.g. `assets.upload({ file })`) accept `fs.ReadStream`, web `File`, a `fetch` `Response`, or the `toFile()` helper output.
- Catch `BeeperDesktop.APIError` (and subclasses) to branch on `err.status`, `err.name`, `err.headers`; rethrow unknown errors.
- Configure retries/timeouts globally at construction (`maxRetries`, `timeout`) or per-request by passing the same options into a call.
- Use `logLevel`/`BEEPER_LOG` env var for debug visibility; inject a custom logger (pino/winston/bunyan/etc.) if not using console.
- For undocumented params, use `// @ts-expect-error` inline rather than fighting the type system; for undocumented endpoints, use `client.get/post` directly.
- For bundle-size-sensitive contexts, use the tree-shakable `createClient` with only the needed resource classes instead of the full default client.

## Anti-Patterns
- Don't assume runtime validation of request/response shapes — the library does not validate or strip data at runtime, so `@ts-expect-error` bypasses are silently trusted; malformed extra fields go through as-is.
- Don't manually paginate with ad-hoc loops when `for await...of` or `page.hasNextPage()/getNextPage()` cover it.
- Don't rely on parsed log message format/content across versions — logs are explicitly for debugging only and may change between releases without a semver-major bump.
- Don't use this library in React Native; it's explicitly unsupported.
- Don't assume `jsdom` works with Jest; only the `"node"` test environment is supported.
- Don't treat internal (non-exported-surface) module internals as stable API, even though some are technically importable, since backwards-incompatible changes there may ship as minor versions.
- Don't disable retries globally assuming safety for non-idempotent calls, and conversely don't assume all errors are retried, only connection errors, 408, 409, 429, and >=500 are retried automatically (2 times, exponential backoff by default).
