## API Surface
The package exposes a single default class, `ImapFlow` (extends `EventEmitter`), instantiated with an `ImapFlowOptions` config object (`host`, `port`, `secure`, `auth`, `proxy`, `logger`, timeouts, etc.).

**Lifecycle**: `connect()`, `logout()`, `close()`, `usable`, `authenticated`, `capabilities`, `enabled`, `serverInfo`.

**Mailbox management**: `list()`, `listTree()`, `mailboxCreate()`, `mailboxRename()`, `mailboxDelete()`, `mailboxSubscribe()`/`mailboxUnsubscribe()`, `status()`, `getQuota()`.

**Mailbox selection (locking)**: `getMailboxLock(path, options)` returns a `MailboxLockObject` with `release()` — the required pattern for opening a mailbox safely. Lower-level `mailboxOpen()`/`mailboxClose()` exist but bypass the lock's concurrency guarantees.

**Message operations**: `search()` (overloaded: plain array or `ESearchResult` via `returnOptions`), `fetch()` (returns `AsyncIterableIterator<FetchMessageObject>`), `fetchAll()`, `fetchOne()`, `download()`/`downloadMany()` (streamed/buffered body parts), `append()`, `messageCopy()`, `messageMove()`, `messageDelete()`, `messageFlagsSet/Add/Remove()`, `setFlagColor()`.

**Idle/events**: `idle()`, plus EventEmitter events — `exists`, `expunge`, `flags`, `mailboxOpen`, `mailboxClose`, `close`, `error`, `log`.

**Diagnostics**: `stats()`, `unbind()` (raw socket detachment), `noop()`.

## Usage Patterns
- Always wrap mailbox access in `getMailboxLock()`/`lock.release()` inside a `try/finally` to guarantee release even on error and avoid concurrent mailbox state corruption.
- Use `for await (const msg of client.fetch(...))` for streaming large result sets instead of `fetchAll()` when the message count is unbounded, to bound memory use.
- Instantiate one `ImapFlow` client per connection; reuse the connection across operations rather than reconnecting per call — `connect()`/`logout()` bracket a session, not each command.
- Pass `logger: false` in production if a custom pino-compatible logger isn't wired up, or supply one to integrate with app-wide structured logging.
- Prefer UID-based ranges (`options.uid: true`) over sequence numbers for any operation that persists identifiers across sessions, since sequence numbers are unstable across mailbox state changes.
- Use `search()` with `returnOptions` (ESEARCH/RFC 4731) plus `partial` paging for large mailboxes instead of pulling all UIDs at once.
- Attach an `expungeHandler` or listen for `expunge`/`exists` events to keep local caches in sync when idling.

## Anti-Patterns
- Don't call `mailboxOpen()` directly without going through `getMailboxLock()` when multiple async operations might run concurrently on the same client — the lock exists specifically to serialize mailbox access; skipping it is a documented source of state corruption.
- Don't forget to call `lock.release()` — a leaked lock stalls all subsequent mailbox operations on that client. The `maxLockHoldTime` option only warns/logs about this, it doesn't auto-recover.
- Don't use `fetchAll()` for unbounded or very large message ranges — it buffers every message in memory; use the async-iterator `fetch()` instead.
- Don't rely on sequence numbers (`seq`) for cross-session references — they shift as messages are expunged; use `uid` instead.
- Don't call IMAP commands before `connect()` resolves or after `logout()`/`close()` — the client is not usable outside an active session (`usable` reflects this).
- Don't assume every server supports extensions referenced in options (`qresync`, CONDSTORE, OBJECTID, X-GM-EXT-1 labels/threadId) — check `capabilities`/`enabled` before depending on fields like `modseq`, `threadId`, or `labels` being populated.
- Don't mix `disableAutoIdle` assumptions with manual `idle()` calls without handling the returned promise's resolution semantics (`idle()` resolves when IDLE ends, not immediately).

## Constraints
- Version 1.3.3 targets Node.js environments consuming CommonJS (`main: lib/imap-flow.js`) with bundled TypeScript types (`lib/imap-flow.d.ts`); no ESM-only entry point.
- `search()` has two overload signatures: without `returnOptions` it resolves `number[] | false` (legacy behavior); with `returnOptions` it can resolve `ESearchResult | number[] | false` — callers must branch on whether they passed `returnOptions`.
- `bigint` is used for UIDVALIDITY, modseq, and similar 64-bit IMAP values, requiring bigint-aware handling (comparisons, JSON serialization) throughout consuming code.
- Depends on a fixed set of pinned sibling/utility packages (`@zone-eu/mailsplit`, `nodemailer`, `libmime`, `iconv-lite`, `socks`, `pino`, etc.) at specific versions; upgrading imapflow may require compatible versions of these.
- `acquireTimeout` on `getMailboxLock` and `maxLockHoldTime` are diagnostic/timeout aids, not deadlock prevention — a hung lock still requires explicit `release()` or timeout configuration to recover.
- OAuth2, proxy (HTTP CONNECT/SOCKS), and compression (COMPRESS=DEFLATE) support are conditional on server capability negotiation and can be forcibly disabled via `disableCompression`/`disableAutoEnable`, but are not guaranteed available on all servers.
- `emitLogs`/`logRaw` expose potentially sensitive raw protocol traffic (including credentials in some auth flows) in log output; must be gated appropriately for production use.
