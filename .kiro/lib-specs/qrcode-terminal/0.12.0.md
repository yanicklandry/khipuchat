## API Surface
**Module export** (`require('qrcode-terminal')`):

- `qrcode.generate(input, [opts], [callback])`
  - `input` (String, required) - the data to encode (text, URL, etc.)
  - `opts` (Object, optional) - options hash
    - `small` (Boolean) - when `true`, renders a compact QR code suitable for terminals with limited space
  - `callback` (Function, optional) - `function(qrcodeString)`; when provided, the rendered QR code is passed as a string instead of being printed directly to stdout
- `qrcode.setErrorLevel(level)`
  - `level` (String) - one of `'L'`, `'M'`, `'Q'`, `'H'` (QR error-correction levels, low to high robustness); default is `'L'`

**CLI binary** (`qrcode-terminal`, installed via `-g`):
- `qrcode-terminal '<data>'` - prints QR code to terminal
- `qrcode-terminal --help`
- Accepts piped stdin: `echo '<data>' | qrcode-terminal`

## Usage Patterns
- Basic terminal output:
  ```js
  var qrcode = require('qrcode-terminal');
  qrcode.generate('This will be a QRCode, eh!');
  ```
- Setting error correction before generating (must be called prior to `generate`, applies to subsequent calls):
  ```js
  qrcode.setErrorLevel('Q');
  qrcode.generate('data with error level Q');
  ```
- Capturing output as a string instead of printing (useful for logging, writing to file, or embedding in other output) via the trailing callback argument:
  ```js
  qrcode.generate('http://github.com', function (qrcode) {
    console.log(qrcode);
  });
  ```
- Compact rendering for constrained terminal width, with or without a callback:
  ```js
  qrcode.generate('This will be a small QRCode, eh!', {small: true});
  qrcode.generate('This will be a small QRCode, eh!', {small: true}, function (qrcode) {
    console.log(qrcode);
  });
  ```
- CLI ad hoc generation or piping data from another command into the tool.
- Cross-platform: supported on OS X, Linux, and Windows terminal environments.

## Anti-Patterns
- Do not call `qrcode.generate(input, callback)` and also expect terminal auto-printing: when a callback is supplied, output is handed to the callback instead of (not in addition to) being printed directly - if you need it on screen you must `console.log` it yourself.
- Do not rely on this library for server-side or non-terminal rendering (e.g., generating an image/canvas/PNG). It is purpose-built for ANSI/ASCII terminal output; use `node-qrcode` (canvas-based) for server-side or graphical rendering needs.
- Do not assume `setErrorLevel` is scoped per-call - it is global/module-level state, so calling it affects all subsequent `generate` calls until changed again. Don't assume thread/call isolation in concurrent contexts.
- Do not pass non-string/malformed `opts` positionally where a callback is expected (or vice versa) - the API distinguishes them by argument position and type, so swapping `opts` and `callback` order will break.
- Do not expect fine-grained control over QR version/size/margins beyond the `small` boolean and `setErrorLevel` - the API intentionally has a minimal surface with no other configuration knobs (no colors, no custom quiet-zone, no output format selection beyond terminal string).
