## API Surface
The package exposes a single primary class, `Client` (extends `EventEmitter`), plus supporting types and auth strategy classes.

**Client** — construct with `new Client(options: ClientOptions)`, then call `initialize()`. Key properties: `info: ClientInfo`, `pupPage`/`pupBrowser` (Puppeteer handles), `interface: InterfaceController`.

Method groups:
- **Lifecycle**: `initialize()`, `destroy()`, `logout()`, `resetState()`, `getState()`, `getWWebVersion()`
- **Auth**: `requestPairingCode()`, `cancelPairingCode()` (QR auth is implicit via the `qr` event and `authStrategy`)
- **Messaging**: `sendMessage()`, `sendReaction()`, `sendSeen()`, `searchMessages()`, `getMessageById()`, `getPinnedMessages()`, `getPollVotes()`, `sendResponseToScheduledEvent()`, `revokeStatusMessage()`
- **Chats**: `getChatById()`, `getChats()`, `archiveChat()`/`unarchiveChat()`, `pinChat()`/`unpinChat()`, `muteChat()`/`unmuteChat()`, `markChatUnread()`, `syncHistory()`
- **Contacts**: `getContactById()`, `getContacts()`, `isRegisteredUser()`, `getNumberId()`, `getFormattedNumber()`, `getCountryCode()`, `getProfilePicUrl()`, `getCommonGroups()`, `getContactDeviceCount()`, `getBlockedContacts()`, address-book methods (`saveOrEditAddressbookContact()`, `deleteAddressbookContact()`), customer notes (`addOrEditCustomerNote()`, `getCustomerNote()`)
- **Groups**: `createGroup()`, `acceptInvite()`/`acceptGroupV4Invite()`, `getInviteInfo()`, membership requests (`getGroupMembershipRequests()`, `approveGroupMembershipRequests()`, `rejectGroupMembershipRequests()`)
- **Channels**: `createChannel()`, `deleteChannel()`, `subscribeToChannel()`/`unsubscribeFromChannel()`, `searchChannels()`, `getChannelByInviteCode()`, `getChannels()`, admin invites (`sendChannelAdminInvite()`, `acceptChannelAdminInvite()`, `revokeChannelAdminInvite()`, `demoteChannelAdmin()`), `transferChannelOwnership()`
- **Labels**: `getLabels()`, `getLabelById()`, `getChatLabels()`, `getChatsByLabelId()`, `addOrRemoveLabels()`
- **Profile/presence**: `setStatus()`, `setDisplayName()`, `setProfilePicture()`, `deleteProfilePicture()`, `sendPresenceAvailable()`/`sendPresenceUnavailable()`, auto-download toggles (`setAutoDownloadAudio/Documents/Photos/Videos`), `setBackgroundSync()`
- **Misc**: `getBroadcasts()`, `getBroadcastById()`, `createCallLink()`, `getContactLidAndPhone()`

**Events** (via `on()`): `qr`, `code`, `authenticated`, `auth_failure`, `ready`, `loading_screen`, `change_state`, `disconnected`, `message`, `message_create`, `message_ack`, `message_edit`, `message_reaction`, `message_revoke_everyone`, `message_revoke_me`, `message_ciphertext`, `message_ciphertext_failed`, `unread_count`, `chat_removed`, `chat_archived`, `group_join`, `group_leave`, `group_admin_changed`, `group_membership_request`, `group_update`, `contact_changed`, `media_uploaded`, `call`, `vote_update`, `remote_session_saved`, `change_battery` (deprecated).

**Auth strategies**: `AuthStrategy` (abstract base), `NoAuth` (QR every run, default when no `authStrategy` given), `LocalAuth` (`{clientId?, dataPath?, rmMaxRetries?}`), `RemoteAuth` (external store-backed, requires a `Store` implementation and `backupSyncIntervalMs`).

**Web version resolution**: `webVersion` + `webVersionCache` (`NoWebCacheOptions | LocalWebCacheOptions | RemoteWebCacheOptions`, discriminated by `type: 'none' | 'local' | 'remote'`).

## Usage Patterns
- Standard bootstrap: instantiate `Client` with `authStrategy: new LocalAuth({clientId})`, register `qr`, `ready`, `authenticated`, `auth_failure`, `disconnected`, and `message` listeners *before* calling `initialize()`, then call `initialize()`.
- Persist sessions across restarts with `LocalAuth` (filesystem) or `RemoteAuth` (custom `Store`, e.g. S3/DB-backed) instead of re-scanning a QR code every run.
- Pass Puppeteer launch flags (headless mode, `--no-sandbox`, executable path, proxy args) through `options.puppeteer`, since whatsapp-web.js drives an actual Chromium instance under the hood.
- Use `requestPairingCode()` + the `code` event as an alternative to QR-code login for headless/server deployments, and call `cancelPairingCode()` to abandon a pending pairing session.
- Look up entities before acting on them: `getChatById()` / `getContactById()` / `getMessageById()` return live objects with additional convenience methods not shown at the `Client` level (media download, quoting, forwarding, etc.).
- Guard outbound messages to unknown numbers with `isRegisteredUser()` or `getNumberId()` since WhatsApp IDs may not correspond to registered accounts.
- Use `message_create` (not `message`) if you need to observe messages the bot itself sends, since `message` only fires for inbound messages.
- Pin `webVersion` + `webVersionCache` explicitly in production to avoid breakage when WhatsApp Web ships an incompatible frontend update; `type: 'remote'` fetches a known-good cached version from a shared endpoint instead of scraping live.
- Media sending/setting (`setProfilePicture`, sticker/webp handling) relies on the `MessageMedia` type and the bundled `fluent-ffmpeg` dependency, so `ffmpegPath` must be a valid binary path if not on `PATH`.

## Anti-Patterns
- Don't call any data-fetching or send method before the `ready` event fires — the Puppeteer page/session isn't fully hydrated yet and calls will hang or throw.
- Don't rely on `ClientInfo.me` or `ClientInfoPhone`; both are explicitly `@deprecated` in this version (`me` → use `wid`; the phone-info block generally doesn't populate under multi-device).
- Don't treat this as an official WhatsApp API: it automates WhatsApp Web via Puppeteer/Chromium, which is against WhatsApp's Terms of Service and can result in the linked number being banned — do not use it for spam, bulk/unsolicited messaging, or mass targeting.
- Don't skip `authStrategy`, expecting persistence "for free" — the default is effectively QR-per-run (`NoAuth`) unless `LocalAuth`/`RemoteAuth` is configured.
- Don't assume `change_battery` is reliable going forward; it's marked deprecated and may be removed in a future release.
- Don't block the event loop / mutate global state synchronously inside event listeners for high-frequency events (`message_ack`, `message`) in busy chats, since messages/acks can arrive in bursts.
- Don't run multiple `Client` instances against the same `LocalAuth`/`clientId` + `dataPath` concurrently; this leads to session/profile lock conflicts. Use `takeoverOnConflict`/`takeoverTimeoutMs` intentionally, not as a default.
- Don't hardcode `webVersion` to `latest`/unpinned in production without a cache strategy — WhatsApp Web updates can silently break the DOM scraping this library depends on.

## Constraints
- Requires Node.js `>=18.0.0` (per `engines`).
- Hard dependency on `puppeteer@24.38.0`, meaning a full Chromium download/runtime is required unless you supply your own `puppeteer.executablePath`; this makes the library heavy for serverless/edge environments and requires compatible sandboxing/OS libs for headless Chromium.
- Functionally coupled to whatever version of the actual WhatsApp Web frontend is live; breaking upstream UI/protocol changes can break this library until it's patched, independent of semver on this package itself.
- `fluent-ffmpeg` is a hard dependency (not optional) used for webp/sticker conversion, so an `ffmpeg` binary must be available or `ffmpegPath` explicitly configured.
- `archiver`, `fs-extra`, and `unzipper` are `optionalDependencies` — features relying on them (e.g., certain `RemoteAuth` archive/backup flows) may silently no-op or throw if these aren't installed.
- `RemoteAuth` requires the caller to supply a custom `Store` implementation; no store is bundled, meaning cloud-persisted sessions require additional integration work.
- No official/typed guarantee of message delivery ordering or exactly-once event delivery, since events are derived from scraping/observing an unofficial web client, not a stable server-side webhook API.
- License is Apache-2.0, and this is an unofficial, community-maintained library (not affiliated with or endorsed by WhatsApp/Meta) — API surface can change between minor versions as WhatsApp's own web client evolves.
- Multi-device WhatsApp accounts are assumed; some legacy single-device fields (`ClientInfoPhone`) are non-functional/deprecated under this constraint.
