## API Surface
The SDK exposes ES/CJS dual-format entry points via subpath exports:

- **`@modelcontextprotocol/sdk`** – root barrel export
- **`@modelcontextprotocol/sdk/client`** – `Client` class with `connect()`, `listTools()`, `callTool()`, `listResources()`, `readResource()`, `listPrompts()`, `getPrompt()`, plus OAuth client provider helpers
- **`@modelcontextprotocol/sdk/server`** – `McpServer` (high-level) and lower-level `Server`; APIs to register tools, resources (including `ResourceTemplate`), prompts, sampling handlers, elicitation (form/URL), logging, and completions
- **`@modelcontextprotocol/sdk/validation`**, **`/validation/ajv`**, **`/validation/cfworker`** – pluggable JSON Schema validation providers (Ajv by default, optional `@cfworker/json-schema`)
- **`@modelcontextprotocol/sdk/experimental`**, **`/experimental/tasks`** – experimental long-running task APIs (poll/resume tool calls); explicitly unstable
- Transports: Streamable HTTP (recommended, stateful or stateless), stdio (local process-spawned servers), and deprecated HTTP+SSE (backwards compatibility only)
- Wildcard `./*` export maps arbitrary deep imports to `dist/esm/*` / `dist/cjs/*`, so internal modules are technically reachable beyond the documented entry points

## Usage Patterns
- Install with the peer dependency explicitly: `npm install @modelcontextprotocol/sdk zod` — Zod is required, not bundled
- Build servers with `McpServer`, register tools/resources/prompts, then `connect()` to a transport (Streamable HTTP for remote/production, stdio for local CLI-spawned integrations)
- Use Streamable HTTP in stateful mode by default; use stateless mode for simple, horizontally-scaled API-style servers with no session tracking
- For server-initiated notifications over Streamable HTTP, add a standalone SSE GET stream alongside the POST endpoint
- Implement resumability with an event store (SDK ships `InMemoryEventStore` as a reference/example, not production-ready)
- Use `Client` on the consumer side; run multiple clients in parallel or issue parallel tool calls when integrating with multiple servers/tools
- For OAuth-protected servers/clients, use the provided OAuth client provider helpers (`client_credentials`, `private_key_jwt`) rather than hand-rolling token exchange
- Use sampling when a tool needs the *client's* LLM to do completion work; use elicitation (form or URL mode) when a tool needs structured or browser-based user input mid-call
- Treat `experimental/tasks` as opt-in and unstable; do not build required functionality on it without a fallback

## Anti-Patterns
- Don't use HTTP+SSE transport for new servers — it's retained only for backwards compatibility with legacy clients; use Streamable HTTP
- Don't ship `InMemoryEventStore` to production — it's an in-memory example for resumability, not durable storage
- Don't assume `globalThis.crypto` (Web Crypto) is present on older Node.js runtimes — JWT-based auth (via `jose`) depends on it; polyfill on Node <18-with-missing-crypto environments per `docs/faq.md`
- Don't treat `experimental/tasks` APIs as stable — they can change across minor/patch versions
- Don't import deep internal paths via the `./*` wildcard export as a substitute for the documented `client`/`server`/`validation` subpaths — those are implementation details, not a stable contract
- Don't bypass the peer dependency contract by pinning an unsupported Zod version — only `^3.25` or `^4.0` are supported, and mixing `zod/v3`/`zod/v4` imports incorrectly can break schema validation
- Don't rely on JSON-response-only mode expecting full notification support — it has limited notification capabilities compared to standard Streamable HTTP with SSE

## Constraints
- **Node.js**: requires `>=18`; older runtimes may need a `globalThis.crypto` polyfill for JWT-based auth features
- **Zod peer dependency**: required (not optional), accepts `^3.25 || ^4.0`; SDK internally uses `zod/v4` APIs while maintaining v3.25+ compatibility
- **`@cfworker/json-schema` peer dependency**: optional, only needed if using the `/validation/cfworker` provider (e.g., for Cloudflare Workers environments without Ajv's codegen-based validation)
- **Module format**: ESM-first (`"type": "module"`), with CJS builds also published (`require` conditions in `exports`) — dual-package hazards possible if mixing import styles across a dependency graph
- **License**: MIT
- **Package boundary**: only `dist/` is published (`files: ["dist"]`); source (`src/`) and examples are not part of the installed package, so runnable examples referenced in docs (`src/examples/...`) exist only in the repo, not in `node_modules`
- **Tasks feature**: `experimental/tasks` subpath is explicitly experimental and outside normal semver stability guarantees for this 1.29.0 release
